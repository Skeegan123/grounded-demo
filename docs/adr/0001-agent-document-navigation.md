# External Agent document navigation is current-only and visibly applied

Grounded exposes `navigate_document` as a focused Document Browsing command. It accepts the identity of the currently accessible Project Document and an optional page, block, or region `target` describing one Document Destination. `DocumentNavigator` resolves that destination without exposing historical document versions. A call succeeds only after the requested Document Destination is rendered and fitted. Block and region destinations fit against the full document viewer without reserving space for floating controls, then receive a transient Document Focus outline. This intentionally replaces the earlier decisions to avoid floating controls and to fit regions without visible decoration. The outline identifies the destination but does not select, annotate, highlight, or classify document content.

A new block or region navigation replaces the prior outline. Document-only or page navigation removes it. Senior Project Manager pan, pinch, wheel, zoom, fit, page-selection, document-selection, and keyboard browsing continue to take control and clear Document Focus. Pointer-down inside the document viewer dismisses only the outline, even when no pan follows, so the fitted region remains in view. Assistance panel interaction does not dismiss it. A repeated navigation to the same dismissed destination creates a fresh outline while reusing an already visible PDF render when possible.

A newer External Agent navigation or Senior Project Manager browsing action supersedes pending navigation, and Assistance state remains untouched. Render failure, cancellation, rollback, and supersession keep their existing ownership rules. The outline appears only for the destination that becomes visibly rendered and fitted, so failed or abandoned work cannot leave stale visual context. This makes tool results describe the view a person can actually see while keeping version history and workflow automation outside the MVP.
